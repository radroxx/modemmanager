## Why

При диагностике «странного» поведения модема (проба не нашла модем, команда получила `ERROR`, регистрация не проходит) сейчас в журнале видно только результат — уровнем логирования его не разжать. Внутри `AtSession` уже есть флаг `trace`, но он никуда не подключён: включить построчный вывод обмена без правки кода нельзя, а по факту это первое, что нужно, когда «модем не отвечает».

Диагностическая трассировка обмена нужна для инцидентов на конкретном модеме, не для повседневной работы: включаться должна явным намерением пользователя и, чтобы не молчала над секретами, использовать существующую маскировку PIN/паролей из `at/guard.py`.

## What Changes

- Обмен AT-командами (исходящие команды и все строки, приходящие из порта) пишется в журнал уровня `DEBUG` как две строки на команду минимум: `<port> > <command>` и `<port> < <line>` для каждой ответной или незапрошенной строки.
- Трассировка включается настройкой `discovery.at_trace` в `settings.json` (по умолчанию выключена). Пока настройка выключена, поведение и объём журнала не меняются.
- Значение PIN-кода и паролей в трассировке заменяется маской `***` через уже существующий `at.guard.mask` — исходящая строка и её эхо (если модем прислал) не должны утечь в журнал.
- Настройка применяется ко всем сессиям, которые открывает приложение: и пробе `discovery.probe`, и обслуживанию модема, и восстановлению после сбоя.

## Capabilities

### New Capabilities

*(нет)*

### Modified Capabilities

- `at-session`: добавляется требование о диагностической трассировке обмена и уточняется, что маскирование секретов распространяется на все записи трассировки, а не только на текст ошибок.

## Impact

- `modemmanager/at/session.py` — существующий флаг `trace` подключается к точкам сессии, где сейчас условно пишутся строки, и распространяется на сессии, которые открывает проба.
- `modemmanager/config.py` — новое поле `DiscoverySettings.at_trace: bool = False`; загрузка/сохранение конфигурации.
- `modemmanager/discovery/probe.py`, `modemmanager/discovery/reconciler.py`, `modemmanager/modem.py`, `modemmanager/at/recovery.py` — фабрика/конструкторы `AtSession` пробрасывают флаг трассировки из настроек.
- `settings_test.json` — пример настройки.
- Тесты `tests/test_at_session.py`, `tests/test_discovery_probe.py` — покрытие включённой трассировки, маскирования PIN, выключенного по умолчанию поведения.
- Публичного API нет. Файл журнала растёт только при явном включении: настройка + `--log-level=DEBUG`.
