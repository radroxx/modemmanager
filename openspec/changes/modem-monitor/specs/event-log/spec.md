## Purpose

Определяет журнал истории сообщений, вызовов и событий оборудования: его формат, состав записей, гарантии записи и правила чтения при неограниченно растущем файле.

## ADDED Requirements

### Requirement: Формат журнала событий

История SHALL храниться в одном файле в формате JSON Lines: одна запись — один объект JSON в одной строке. Файл SHALL быть только дополняемым: существующие записи MUST NOT изменяться и удаляться.

#### Scenario: Записано новое событие

- **WHEN** система формирует событие
- **THEN** она дописывает в конец файла одну строку с объектом JSON и не изменяет ранее записанные строки

#### Scenario: Файл журнала отсутствует

- **WHEN** приложение запускается, а файла журнала нет
- **THEN** система создаёт файл и продолжает работу

#### Scenario: Файл содержит повреждённую строку

- **WHEN** при чтении истории обнаруживается строка, не являющаяся корректным объектом JSON
- **THEN** система пропускает эту строку, продолжает чтение остальных и не завершает работу с ошибкой

### Requirement: Ротация журнала отсутствует

Система MUST NOT выполнять ротацию, сжатие, усечение или удаление журнала событий.

#### Scenario: Файл журнала вырос до большого размера

- **WHEN** файл журнала достигает размера в несколько гигабайт
- **THEN** система продолжает дописывать записи в тот же файл

### Requirement: Обязательные поля записи

Каждая запись SHALL содержать время события, тип события и, если сведения доступны, идентификатор SIM-карты и идентификатор модема.

#### Scenario: Событие относится к опознанной SIM-карте

- **WHEN** записывается событие о полученном сообщении или вызове
- **THEN** запись содержит время, тип, идентификатор SIM-карты, её имя на момент события и идентификатор модема

#### Scenario: Событие относится к неопознанному модему

- **WHEN** записывается событие о модеме, идентификатор SIM-карты которого неизвестен
- **THEN** запись содержит время, тип и доступные сведения об устройстве, а поле идентификатора SIM-карты отсутствует или пусто

### Requirement: Типы записываемых событий

Система SHALL записывать в журнал: полученные сообщения, входящие вызовы, появление и пропадание модема, отсутствие SIM-карты, обнаружение ненастроенной SIM-карты, срабатывание защиты от блокировки PIN-кода, блокировку по PUK, длительное отсутствие регистрации и результаты поиска доступных операторов.

#### Scenario: Пропадание модема зафиксировано

- **WHEN** модем признан отсутствующим
- **THEN** в журнал записано событие соответствующего типа со сведениями об устройстве

#### Scenario: Результат поиска операторов зафиксирован

- **WHEN** завершён поиск доступных операторов
- **THEN** в журнал записано событие со списком найденных сетей и идентификатором SIM-карты

### Requirement: Запись до отправки уведомления

Событие SHALL быть записано в журнал до попытки отправки уведомления и независимо от её результата.

#### Scenario: Уведомление не удалось отправить

- **WHEN** событие сформировано, а отправка уведомления завершилась неудачей
- **THEN** запись о событии присутствует в журнале

### Requirement: Чтение истории с конца файла

Чтение истории SHALL выполняться от конца файла к началу с ограничением количества возвращаемых записей. Полное чтение файла MUST NOT выполняться ни при обслуживании запросов истории, ни при запуске приложения.

#### Scenario: Запрошены последние записи истории

- **WHEN** запрошены последние записи истории при большом размере файла
- **THEN** система возвращает запрошенное количество последних записей, прочитав только конец файла

#### Scenario: Запрошены записи по SIM-карте

- **WHEN** запрошена история конкретной SIM-карты
- **THEN** система возвращает последние записи, относящиеся к этой SIM-карте, читая файл от конца и ограничивая объём прочитанного

#### Scenario: Записей меньше, чем запрошено

- **WHEN** в журнале меньше записей, чем запрошено
- **THEN** система возвращает все имеющиеся записи

### Requirement: Настройки хранятся отдельно от журнала

Настройки SHALL храниться в отдельном файле в формате JSON и SHALL перезаписываться так, чтобы прерывание записи не приводило к потере или повреждению файла настроек.

#### Scenario: Настройки изменены из веб-интерфейса

- **WHEN** пользователь сохраняет изменённые настройки
- **THEN** система записывает новое содержимое так, что при прерывании записи на диске остаётся либо прежняя, либо новая полная версия файла

#### Scenario: Файл настроек отсутствует при запуске

- **WHEN** приложение запускается, а файла настроек нет
- **THEN** система создаёт файл с настройками по умолчанию, сообщает об отсутствии обязательных значений и не завершается аварийно из-за самого факта отсутствия файла

### Requirement: Состояние рантайма не сохраняется на диск

Система MUST NOT создавать дополнительных файлов состояния помимо файла настроек и журнала событий. Соответствие модема и SIM-карты, промежуточные части многочастных сообщений, результаты поиска операторов и вердикты проверки устройств SHALL восстанавливаться опросом оборудования после запуска.

#### Scenario: Приложение перезапущено

- **WHEN** приложение перезапускается
- **THEN** оно восстанавливает сведения о модемах и SIM-картах опросом оборудования, не читая никаких файлов состояния помимо настроек

#### Scenario: Перезапуск во время сборки многочастного сообщения

- **WHEN** приложение перезапускается после того, как часть многочастного сообщения была прочитана и удалена из памяти SIM-карты, но сообщение ещё не собрано
- **THEN** незавершённое сообщение теряется, и это является ожидаемым поведением
