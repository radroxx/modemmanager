## Why

Есть 6-7 USB-модемов двух семейств (Huawei-свистки на драйвере `option1` и модули SIM800 через мост CH340 на `ch341-uart`) с SIM-картами в роуминге. Нужно постоянно знать, живы ли они, зарегистрированы ли в сети и на каком операторе, и не терять входящие SMS и звонки — сейчас это никак не наблюдается, а часть карт молча не принимает SMS по неизвестной причине.

Отдельная цель — сделать систему **измерительным прибором**: собрать наблюдаемые признаки (регистрация CS/PS, PLMN, заполненность памяти SIM, время последней SMS) так, чтобы стало видно, от чего зависит приём SMS в роуминге.

## What Changes

- Новое асинхронное Python-приложение — один процесс, включающий в себя опрос модемов, HTTP-сервер статуса и Prometheus-эндпоинт.
- **Обнаружение модемов** двухступенчатое: дешёвый фильтр по allowlist драйверов в `/sys/bus/usb-serial/drivers/*` с группировкой портов по родительскому USB-устройству, затем probe AT-командами для подтверждения «это модем» и определения семейства. Фильтр по драйверу для `option1` почти достоверен, для `ch341-uart` (универсальный мост) — только сужает круг, поэтому probe обязателен.
- **Взаимодействие с семействами модемов вынесено в классы-стратегии** (поведенческий паттерн): выбор роли порта, строки настройки нотификаций, разбор незапрошенных сообщений, нормализация уровня сигнала, чтение счётчика попыток PIN, лестница восстановления.
- **Транспорт AT** — на порт одна сессия: единственный читающий цикл, очередь команд с одной командой in-flight, классификация незапрошенных сообщений (`RING`, `+CLIP`, `+CMTI`, `^RSSI`, `^BOOT`), таймауты, повторы, переоткрытие порта, софт-ресет.
- **Приём SMS только в PDU-режиме** (`AT+CMGF=0`): текстовый режим не отдаёт UDH и делает сборку многочастных сообщений невозможной. Части склеиваются на уровне сырых октетов/септетов и декодируются один раз — иначе символ, разрезанный границей части, ломает разбор.
- **Освобождение памяти SIM** сразу после чтения сообщения: заполненная память — вероятная причина «SMS не приходят без ошибок».
- **Входящие звонки**: ожидание `+CLIP` для номера, дедуп повторяющихся `RING` в одно событие, отклонение вызова. Приём и инициация вызовов не реализуются.
- **PIN-guard**: попытка ввода PIN только если модем сообщает, что осталось 3+ попытки. При 2 и менее, а также при нечитаемом счётчике — попытка не делается вообще, отправляется уведомление. Восстановление физическое (SIM в телефон), обхода guard в UI нет.
- **Уведомления в Telegram** с маршрутизацией `ICCID -> chat_id`; события уровня системы (нет SIM, модем пропал, PIN-guard, незнакомая SIM, нет регистрации) идут в `admin_chat_id`.
- **Выбор оператора** — ручная привязка PLMN с возможностью выбрать в UI из результатов явно запускаемого скана сети; watchdog уведомляет, если модем не может зарегистрироваться на заданном операторе.
- **Страница статуса** — список модемов, статус, уровень сигнала, оператор и роуминг, вставленная SIM с её ICCID и человекочитаемым именем; редактирование номера, PIN, предпочитаемого оператора; история SMS и звонков. Символическая авторизация одним паролем.
- **`/metrics`** для Prometheus, без авторизации.
- **Хранение**: все настройки в одном `settings.json`, история в `events.jsonl` (JSON Lines, append-only, без ротации). Никаких других файлов состояния: соответствие модем↔SIM и буферы сборки SMS живут в памяти.

### Non-goals (явно вне scope)

- **Отправка SMS** — не реализуется. Команды `AT+CMGS`, `AT+CMSS` и подобные запрещены на уровне транспорта.
- **Исходящие звонки и ответ на входящие** — не реализуются. `ATD` запрещён. Карты в роуминге, любой такой трафик стоит денег.
- **Передача данных / PPP** — не реализуется.
- Шифрование секретов: пароль UI и PIN-коды хранятся в `settings.json` открытым текстом осознанно. PIN не отображается в UI и не попадает в логи и метрики.
- Многопользовательская авторизация, роли, HTTPS.
- Ротация и архивация `events.jsonl`.

## Capabilities

### New Capabilities

- `modem-discovery`: фильтрация usb-serial портов по allowlist драйверов, группировка портов по USB-устройству, probe и выбор семейства, негативный кэш, обнаружение появления и пропадания модемов через сверку желаемого с фактическим.
- `at-session`: транспорт AT-команд на одном последовательном порту — очередь команд, единственный reader, разбор многострочных ответов, классификация незапрошенных сообщений, таймауты, лестница восстановления, запрет платных команд.
- `modem-behaviors`: контракт стратегии для семейства модемов и его реализации для Huawei, SIM800 и generic-AT; что именно варьируется между семействами.
- `sim-management`: идентичность SIM и модема (ICCID, IMEI), автоимя и пользовательское имя, состояния SIM (нет SIM, требуется PIN, PUK, готова), PIN-guard, редактируемые настройки SIM, ручной выбор PLMN, скан сети, watchdog отсутствия регистрации.
- `sms-receive`: приём SMS в PDU-режиме, разбор PDU, сборка многочастных сообщений, освобождение памяти SIM, выгребание накопившихся сообщений при старте, обработка незавершённых групп.
- `call-notify`: обнаружение входящего вызова, получение номера из `+CLIP`, дедуп `RING`, отклонение вызова, формирование события.
- `notifications`: доставка событий в Telegram, маршрутизация по ICCID и admin-канал, очередь с повторами, дедуп повторяющихся состояний.
- `event-log`: формат `events.jsonl`, типы записей, гарантии записи, чтение последних N записей через seek от конца файла.
- `web-interface`: HTTP-сервер в том же процессе — страница статуса, история, API настроек с write-only полем PIN, символическая авторизация, `/metrics` для Prometheus без авторизации.

### Modified Capabilities

Нет — проект новый, существующих спецификаций нет.

## Impact

- **Новый код**: весь. Репозиторий сейчас содержит только README, LICENSE и `.gitignore`.
- **Стек**: Python 3, `asyncio`. Новые зависимости: асинхронная работa с последовательным портом, HTTP-сервер, клиент Telegram Bot API, экспортёр Prometheus. Разбор PDU — свой, готовых зависимостей не предполагается.
- **Системные требования**: доступ на чтение и запись к `/dev/ttyUSB*` (сейчас устройства принадлежат `root` и группе, в которой процесса нет) — понадобится udev-правило или добавление в группу. На хостах с ModemManager потребуется исключение портов из его управления, иначе он будет конкурировать за AT.
- **Данные**: два файла — `settings.json` (секрет, права `0600`) и `events.jsonl` (растёт неограниченно).
- **Внешние сервисы**: Telegram Bot API (исходящие HTTPS). Prometheus скрейпит `/metrics`.
- **Риски**: у Huawei 12d1:1001 пустой USB serial, поэтому идентичность железа берётся только из IMEI; счётчик попыток PIN читается разными командами и не всеми прошивками; SIM800 на USB склонен к просадкам питания и самопроизвольным переподключениям, что требует дебаунса перед объявлением модема пропавшим.
